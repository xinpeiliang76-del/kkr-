静态博客到底是怎么回事

2026-10-21技术博客

一开始我以为做博客必须租一台服务器，装个 WordPress，再备案、配数据库、装插件、定期升级、被扫描器爆破……光想想就累了。

后来发现对"只是写文章"这件事来说，上面那些全是多余的动作。

动态博客在做什么

传统博客（WordPress、Typecho 这类）每来一个访客，服务器上的 PHP 就要跑一遍：从数据库查文章、拼 HTML、再发回去。所以你需要 CPU、内存、数据库、备份、安全补丁。

问题是我一个月写两篇文章，访客大概只有我自己和三个误入的爬虫。为了这点流量养一台机器，性价比极低。

静态博客在做什么

静态博客把"拼 HTML"这一步提前到我自己的电脑上，在发布的时候一次性做完。服务器（或者说托管）只需要做一件事：把一个已经是 HTML 的文件原样发出去。

于是：

动态博客静态博客
需要服务器是不需要
需要数据库是不需要
被入侵风险有几乎没有（没有可执行的代码）
打开速度看机器和优化很快，就是发文件
花钱服务器 + 域名通常 0 元
缺点维护成本没有评论、搜索等现成功能

那评论区怎么办

静态博客没有后端，所以评论要么用第三方服务（ utterances 用 GitHub Issues、giscus 用 GitHub Discussions、Disqus），要么干脆不要。

我倾向于先不要。一个没什么人看的博客，最需要的不是评论区，是继续写下去。

迁移成本

万一以后真的需要动态功能，Markdown 文章是通用的。换个生成器、换台服务器、迁到别的地方，正文一个字都不会丢。

这就是我选它的真正原因：内容和技术方案解耦了。 平台会倒闭，工具会过时，.md 文件不会。
