从零做一个自己的网站：给普通人的教程

2026-10-24教程建站

这份教程写给不会写代码的人。跟着做完，你会有一个自己的网址，别人可以用手机打开。

全程不需要服务器、不需要备案、不需要付费。需要准备的只有三样：一台 Windows 电脑、一个邮箱、大约四十分钟。

先说清楚几件事

你会做出什么。一个静态网站：一堆已经写好的网页文件，放到 GitHub 的免费托管上，拿到类似 你的用户名.github.io/仓库名/ 的网址。

为什么不用服务器。服务器是给"每次访问都要现场计算"的网站用的，比如论坛、商城。博客不需要现场计算，网页提前做好，谁来都是发同一个文件。既然只是发文件，就不必自己养一台机器。

代价是什么。没有后台管理界面，写文章靠改文本文件；国内访问 GitHub 的免费托管有时会慢，甚至打不开（后面有解决办法）。

你需要装什么。只有一个：Node.js。其他都是可选项，装不装都能做完。

第一步：装 Node.js

Node.js 是用来"把 Markdown 变成网页"的工具。打开：

<https://nodejs.org/zh-cn>

点页面上那个绿色的大按钮下载 LTS 版本（LTS 是长期支持版，选它，不要选 Current）。下载下来是个 .msi 文件，双击安装。

安装过程中只注意一件事：保持默认选项，一路点"下一步"。默认会勾上 "Add to PATH"，这一项很重要，不要取消。

装完验证一下。按键盘上的 Win + R，输入 cmd，回车，会弹出一个黑窗口——这个叫"命令提示符"，后面还会用到。在里面输入：

node -v

回车。如果显示类似 v22.11.0 的一行，说明装好了。

如果显示"不是内部或外部命令"，八成是安装时没有勾 PATH，或者黑窗口是在安装之前就开着的。关掉黑窗口重新开一个再试；还不行就重装一遍 Node.js。

第二步：拿到网站的源码

这个站的全部文件就是一个文件夹。两种拿法：

方法一，下载压缩包。打开仓库页面，点绿色的 Code 按钮 → Download ZIP，解压到桌面。会得到一个 blog 文件夹。

方法二，如果你已经装了 Git。在命令提示符里：

git clone https://github.com/xinpeiliang76-del/kkr-.git

第三步：在本地把它跑起来

打开 blog 文件夹，你会看到这些：

名字作用
posts文章，每篇一个 .md 文件
pages独立页面（比如"关于"）
site.config.json站点名字、简介、导航
theme.json颜色和字号
assets样式表
docs生成出来的网页（自动产生，不用手改）
启动编辑器.cmd双击运行的按钮

双击 本地预览.cmd。会弹出一个黑窗口，同时浏览器自动打开 http://localhost:4000，你就能看到网站了。

黑窗口不要关，它就是服务器。关掉网站就打不开了。

localhost 的意思是"这台电脑自己"。所以这个地址只有你能打开，别人打不开——这是正常的，等第六步发布出去才是给人看的。

第四步：改文字

改站名和简介

用记事本（或者更好的编辑器，见后面的软件清单）打开 site.config.json，会看到这样的内容：

{
  "title": "冲突、纠错与解放",
  "shortTitle": "冲突与纠错",
  "description": "这里是一句介绍",
  "author": "你的名字",
  "github": "https://github.com/你的用户名",
  "nav": [
    { "name": "纲要", "path": "manifesto.html" }
  ],
  "cover": {
    "kicker": "CONFLICT · CORRECTION · EMANCIPATION",
    "title": "冲突、纠错与解放",
    "subtitle": "——副标题写在这里",
    "note": "文 / 你的名字 · 2026"
  },
  "pillars": [
    { "num": "壹", "name": "第一条", "text": "这一条说了什么。" }
  ]
}

规则很简单：引号里的字改成你的，冒号和逗号不要动，引号不要丢。

改完保存，回到浏览器按 F5 刷新。没变化就说明黑窗口里的程序没重新跑——见下面的"改完没反应"。

写一篇新文章

在 posts 文件夹里新建一个文本文件，名字必须遵守这个格式：

2026-10-25-我的第一篇文章.md

前半截是日期，后半截会变成网址，所以发布以后别改名，改了旧链接就打不开。

用记事本打开，第一段写两行开头的"说明书"：

---
title: 我的第一篇文章
tags: 随笔
---

正文从这一行开始写。

两条横线之间的部分是给程序看的，title 是标题，tags 是标签。下面的正文用 Markdown 写。

Markdown 就这三样够用了

标题：行首写两个井号加一个空格：

## 这是一个小标题

加粗：用两个星号包起来：**这几个字会变粗**

列表：行首一个减号加空格：

- 第一项
- 第二项

链接写成 [显示的文字](https://网址)，粗体写成 **文字**，够写博客了。想看更多语法，网上搜"Markdown 语法"随便一篇都能对照。

改完没反应？

docs 里的网页不是自动更新的。三种办法让它重新生成：

  • 双击 生成网站.cmd；
  • 或在命令提示符里进入 blog 文件夹，运行 node build.js；
  • 或者用下一步的编辑器，它保存时会自动重新生成。

第五步：换颜色和样式

这是最省事的一部分。双击 启动编辑器.cmd，浏览器会打开一个编辑界面：左边是调色面板，右边是真实网站的实时预览。

能改的东西：

  • 预设方案：六种配色，点一下立刻套用，包括朱红纸本、靛蓝冷灰、墨黑极简等；
  • 亮色 / 暗色：分别调纸色（背景）、墨色（文字）、强调色、线条色。暗色是系统切到深色模式时自动生效的那套；
  • 字号、行高、版心宽：三个滑杆，拖的时候右边马上跟着变；
  • 字体：宋体、黑体、楷体、系统界面、等宽，五选一。

调满意了点 「保存并重新生成」，改动写进 theme.json，docs 里所有页面同时更新。想反悔就点「恢复默认」。

编辑器只改颜色和排版，不改文字。文字仍然在 posts 和 pages 里改——这样分工其实更安全：配色永远不会把你的文章改坏。

如果连双击都嫌麻烦，也可以直接打开 theme.json 改里面那几行十六进制颜色值，效果一样。

第六步：发布到 GitHub Pages

到这一步，网站还只在你电脑上。发布就是把它传到 GitHub。

注册

打开 <https://github.com/signup>，用邮箱注册，验证邮箱。免费账号就够。

建仓库

登录后点右上角的 + → New repository。名字随便起，比如 my-blog；可见性选 Public（公开）；下面的 "Add a README file" 之类都不要勾。点 Create repository。

传文件

进入刚建好的仓库，点 Add file → Upload files。

这一步有个坑：要把 blog 文件夹里面的东西全选拖进去，而不是把 blog 文件夹本身拖进去。拖文件夹的话会多出一层目录，后面设置对不上。

具体操作：打开 blog 文件夹，按 Ctrl + A 全选，把 assets、docs、pages、posts、build.js、editor.js、site.config.json、theme.json 这些一起拖到网页的上传区，然后点页面下方的 Commit changes。

打开 Pages

进仓库的 Settings（顶部菜单） → 左侧栏找 Pages → 在 Source 里选 Deploy from a branch → 分支选 main，目录选 /docs → 点 Save。

等一到两分钟，刷新这个页面，顶会出现一行绿字：Your site is live at https://....github.io/..../——那就是你的网址。

网址长什么样

仓库叫 my-blog，用户名是 xiaoming，网址就是：

https://xiaoming.github.io/my-blog/

如果仓库名恰好是 xiaoming.github.io，网址就是 https://xiaoming.github.io/（没有后面的路径）。

打不开怎么办

  • 404：先看 Pages 设置里的目录是不是 /docs，再确认仓库里确实有 docs 文件夹，且里面有 index.html；
  • 构建失败：点仓库顶部的 Actions 标签，红色叉号点进去看报错；
  • 很慢或打不开：这是国内访问 GitHub 免费托管的常见情况。可以换个托管：注册 Cloudflare Pages 或 Vercel，用同一个 GitHub 仓库导入，几分钟就能得到一个更快的地址，网站文件一个字都不用改。

第七步：以后怎么更新

改了文章或颜色之后，需要重新上传。两条路：

装 Git（推荐，一次麻烦，长期省事）。下载安装：<https://git-scm.com/download/win>，安装时全部默认。然后在 blog 文件夹里右键选择"在终端中打开"，依次运行：

git add .
git commit -m "更新文章"
git push

第一次推送会要求登录。注意：不能用账号密码，要去 GitHub 设置里生成一个 Token 当密码用（Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token，勾选 repo，复制那串 ghp_ 开头的字符）。

不装 Git。回到仓库页面，Add file → Upload files，把改动过的文件重新拖上去，提交。笨但有效。

常见问题

"node 不是内部或外部命令"

Node.js 没装，或者装了没重启命令行窗口。关掉黑窗口重新开。

双击 cmd 文件闪一下就没了

说明 Node.js 没装好。手动打开黑窗口，用 cd 进到 blog 目录再运行 node build.js，就能看到具体报错。

改了文章但网址上还是旧的

本地改完必须重新生成（编辑器保存会自动生成，其余情况要跑 node build.js），然后还要把 docs 里的新文件也传上去。两件事都做了才会变。

能上传但仓库里没有 docs 文件夹

GitHub 网页上传会跳过以点开头的文件（比如 .gitignore），也可能在拖拽时漏掉子文件夹。传完点进仓库看一眼，缺了就用 Add file → Create new file，文件名写 docs/index.html 手动补。

想让网站私有

Settings → 最下方 Danger Zone → Change visibility → Make private。注意：私有仓库的 GitHub Pages 需要付费账户，转私有后网站会下线。

想要评论功能

静态站没有后端。常见做法是接 giscus（把评论存在 GitHub Discussions 里，免费无广告），在 GitHub 上搜 giscus 按它的引导做。

术语表

静态网站：网页是提前做好的文件，访问时原样发出去，不现场计算。

Markdown：一种用纯文本写文章的格式，用 ## 表示标题、** 表示加粗，写完能转成网页。

仓库（repository）：GitHub 上的一个文件夹，存着网站的全部文件和历史版本。

分支（branch）：仓库里的一条时间线，默认叫 main，就是主线。

GitHub Pages：GitHub 提供的免费网站托管，把文件放上去就给你一个网址。

localhost：指"这台电脑自己"。所以 localhost:4000 只有你能打开。

终端 / 命令提示符：黑色的窗口，用输命令代替点鼠标。Win + R 输入 cmd 打开。

这套东西没有一处是必须的，除了那台电脑和那个邮箱。如果中途卡住，把报错原文贴出来问人，比描述"它坏了"有用得多。
